# Real-Data Track (isolated)

> Status: **ready-to-run, isolated from the production demo** — the demo still serves
> the deterministic synthetic proxy dataset.

## Why this exists

CreditFlow's running demo trains and serves on
`data/creditflow_dataset.csv`, a **deterministic synthetic proxy dataset**
(generated by `pipeline/data/generate_dataset.py`, seed 42). That is intentional:
it makes the ML pipeline fully reproducible and demoable anywhere.

To also prove the project is **designed to migrate to real credit data**, we
added a separate **real-data track** that maps an external dataset to the
CreditFlow canonical schema and validates it — *without ever silently changing
the production model*.

> **Engineering quote for interviews:**
> "The demo currently runs on a deterministic synthetic proxy dataset. I
> deliberately isolated real-data ingestion from the serving path so the
> production demo isn't silently changed before validating the real dataset."

## Files

```
pipeline/data/mapping.yaml     # mapping config (raw columns -> canonical schema)
pipeline/data/ingest.py        # isolated ingest: map -> validate -> manifest (SHA-256)
data/raw/.gitkeep              # place raw source CSV(s) here (git-ignored content)
data/processed/                # normalized output + sha256 (written by ingest)
data/metadata/dataset_manifest.json   # provenance / readiness (written by ingest)
docs/data/real-dataset.md      # this document
```

## How to use (when you have a real dataset)

```bash
pip install pyyaml

python -m pipeline.data.ingest \
    --raw data/raw/my_dataset.csv \
    --out data/processed/creditflow_real.csv \
    --meta data/metadata/dataset_manifest.json
```

Outputs:

- `data/processed/creditflow_real.csv` — mapped + normalized
- `data/metadata/dataset_manifest.json` — rows, positive_rate, sha256,
  missing columns, dropped columns, validation violations, `ready_for_training`

The manifest is the source of truth for whether a real dataset is ready to
train on (`ready_for_training: true`). Until then, the demo keeps using the
synthetic proxy.

To force-regenerate the synthetic demo proxy (deterministic, same output):

```bash
python -m pipeline.data.ingest --synthetic-demo
```

## Reference mapping: German Credit (UCI)

`mapping.yaml` ships with a `german_credit` (UCI Statlog) mapping as a
worked example. Honest findings for that dataset:

- Maps cleanly: `age`, `credit_amount -> loan_amount`, `duration -> loan_term`.
- Does **not** cleanly map to 5 of the 8 canonical features (`income`,
  `employment_years`, `existing_debt`, `credit_history`, `previous_defaults`)
  — German Credit uses categories/counts, not continuous amounts/years.
- Therefore `ready_for_training` for German Credit is **false** out of the box.

This is *not* hidden: the manifest reports every missing/unmapped/dropped
column with a reason. Bringing in a dataset that does map the 8 features
(e.g. a Kaggle Home Credit subset after engine-driven feature mapping) is the
follow-up — and requires owner review of semantics before any retrain.

## Migration safety

- `scripts/train_models.py` and the FastAPI backend **do not read** ingest
  outputs; they keep using `data/creditflow_dataset.csv`.
- Ingest only writes to `data/processed/` and `data/metadata/`.
- No dataset is retrained/registered unless you explicitly run a training on a
  mapped dataset that passes validation and owner review.
- Never compare raw F1/business-cost across datasets as if they were the same
  problem; compare the *engineering path* and validate semantics first.
